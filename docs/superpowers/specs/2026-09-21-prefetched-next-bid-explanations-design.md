# 下一步建议真实解释预取设计

## 目标

将“下一步建议”中的概括性文本替换为原新睿接口返回的真实叫品解释。点击建议项时直接执行该叫品，推进叫牌进程，并立即为新状态预取下一轮建议。

## 交互

- 页面初次载入，以及叫牌、撤销、清空、切换体系、切换赛制或切换牌副后，重新计算合法下一叫。
- 下一步建议保持现有顺序：特殊叫品 `P/X/XX` 优先，其余叫品按级别与花色顺序排列。
- 查询期间每项显示“正在查询…”，但仍可点击执行合法叫品。
- 查询成功后显示真实解释；需要 ALERT 时，在解释后显示加粗的 `🅰︎` 标记，不再显示文字 `· ALERT`，且标记不链接到外部网站。
- 无解释时显示“暂无说明”；服务不可用时显示“说明暂时不可用”。一个失败项不影响其他项。
- 点击建议项后立即加入叫牌历史、更新合法叫品、当前座位和终局状态，然后查询新一轮建议。
- 历史叫品仍可点击查询其真实解释。
- 页面底部增加低调的出品署名：“北京析构整环桥牌俱乐部出品”。

## 数据流

浏览器调用同源 `POST /api/explanations`。请求必须是 `application/json`、正文不超过 16 KiB，并来自同源导航环境；拒绝跨源 `Origin` 或 `Sec-Fetch-Site: cross-site`。精确请求结构为：

```json
{
  "system": "CBB",
  "dealer": "N",
  "vul": "None",
  "teammode": 0,
  "sequences": ["P", "1C", "1D"]
}
```

`system` 只允许 `JQA/CBB/NBS/ASY`，`dealer` 只允许 `N/E/S/W`，`vul` 只允许 `None/NS/EW/All`，`teammode` 只允许整数 `0/1`。`sequences` 必须包含 1–40 个互不重复的字符串；每个字符串转成大写后由 1–320 个合法叫品组成，用 `_` 分隔，总长度不超过 1,024 字符。任意字段、重复项或序列非法会使整批返回 HTTP 400，且不会访问上游。

服务器验证请求后，以最多 4 个并发请求访问原接口，并按输入顺序返回：

```json
{
  "results": [
    {
      "sequence": "1N",
      "status": "found",
      "explanation": "15–17点，均衡牌型",
      "isAlert": false,
      "source": "upstream"
    }
  ]
}
```

每个结果包含：

- `sequence`
- `status`: `found | missing | unavailable`
- `explanation`（仅 `found`）
- `isAlert`（仅 `found`）
- `source`（仅 `found`），允许值为 `upstream | cache`；`missing` 和 `unavailable` 不带此字段

共享的 `sessionid` 与 `uid` 继续只存放在 Sites 后端秘密中，不返回浏览器、不写入网页源码。

现有 `POST /api/explain` 保持兼容，继续供历史叫品单项查询使用。历史第 `n` 个叫品使用从开叫到第 `n` 个叫品为止的完整前缀查询。

## 并发、限流与过期结果

- 浏览器为每轮查询分配递增编号，并使用 `AbortController` 取消上一轮。取消仅用于客户端保鲜，不假设它一定能取消已经发出的 Worker 上游请求。
- 查询身份包含：叫牌序列、体系、发牌人、局况、赛制和牌副编号。只有完整身份仍匹配且编号仍为最新的结果可以写入列表。
- 服务器最多同时执行 4 个上游请求。D1 原子令牌桶在上游请求前限制公开批量端点：每个来源地址每分钟 8 批、突发 4 批；全站每分钟 30 批、突发 10 批。超限返回 429 和 `Retry-After`，不访问上游。来源地址使用后端秘密 `RATE_LIMIT_HMAC_KEY` 做 HMAC-SHA-256 后再作为 D1 键保存，避免可枚举的裸 IP 哈希。桶记录带最后更新时间；请求过程中顺带删除 24 小时未更新的来源桶，全站桶长期保留。D1 不可用、事务失败或缺少 HMAC 密钥时，批量端点失败关闭并返回 503，不访问上游。
- D1 缓存以体系、发牌人、局况、赛制和完整序列为键保存成功说明 6 小时；命中缓存不消耗上游调用。缓存缺失项才进入最多 4 并发的上游队列。
- 每个上游调用 8 秒超时，响应正文最多 16 KiB。批量端点总执行时间最多 20 秒；未完成项归一化为 `unavailable`。
- 批量接口最多接受 40 个序列，拒绝重复、越界或格式非法的请求。
- 建议点击时必须针对当前叫牌重新计算合法叫品；若旧行已过期或连续点击导致该叫品不再合法，则不追加。第一次点击后同步禁用并清除旧建议，再推进状态，防止双击。

## 错误处理

- 整批格式、正文大小、内容类型或同源检查错误返回 HTTP 400/413/415/403。
- 单个上游查询失败只将对应项标记为 `unavailable`，批量响应仍为 HTTP 200。
- 缺少后端密钥时，所有合法项返回 `unavailable`，且不泄露配置细节。
- 上游超时、网络错误、非 2xx、JSON 非法、响应过大或 `rcode` 非 `0000` 映射为 `unavailable`；只有 `rcode` 为 `0000` 且解释为空白时映射为 `missing`；缺失 `isalert` 按 `false` 处理。
- 页面保留合法叫品和当前输入，不因解释服务故障阻塞叫牌。
- 终局时取消当前预取并显示“叫牌已结束”，不提交空批次。

## 验证

- 单元测试覆盖：批量顺序、最多 4 并发、部分失败、40 项边界、16 KiB 正文、非法/重复序列、同源检查、D1 全站/来源限流、缓存命中和密钥不泄露。
- 页面行为测试覆盖：建议点击会重新验证并加入叫牌；连续点击只追加一次；加载、缺失、不可用和加粗 `🅰︎` ALERT 标记正确渲染，且标记不是链接。
- 页面内容测试覆盖底部准确显示“北京析构整环桥牌俱乐部出品”。
- 测试每一种上下文变化（叫牌、撤销、清空、体系、赛制、牌副）后的迟到响应均不会覆盖新状态，并覆盖终局取消和空状态。
- 服务测试覆盖精确上下文转发、上游超时、非 2xx、超大正文和畸形 JSON 的归一化。
- 保留现有标准 16 副局况循环测试。
- 发布后使用确定的 `CBB / N / None / 1N` 线上批量查询，要求结果为 `found` 且 `source` 为 `upstream` 或 `cache`；随后在页面点击该建议，确认它进入历史并触发下一轮加载。
